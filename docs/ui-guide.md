# UI-гайд «Орбиты» — для агентов

> Короткая **актуальная** дизайн-система. Читай перед любой работой с интерфейсом.
> История решений и отклонённые версии — в `docs/design.md` (только для контекста, не как образец).
> Эталон вживую — сам сайт (`web/`) и утверждённые макеты: `today-desktop-v4.html`, `study-v1.html`, `time-v3.html`, `office-v1.html`, `login-v1.html` в `docs/design/mockups/`.

## 1. Суть стиля

Тёмный (по умолчанию), спокойный, просторный, премиальный — уровень Apple / Linear / Notion. **Монохромный интерфейс, цвет только в контенте**: цвет курса, статус, иллюстрации. Иерархия — размером и насыщенностью шрифта, а не рамками и цветом.

## 2. Токены (`web/src/app/globals.css`, светлая тема — класс `.light`)

| Назначение | Токен |
|---|---|
| Фон страницы | `--bg` (#131315, не чёрный) |
| Поверхности: карточка → hover → вложенное | `--s1` → `--s2` → `--s3` |
| Hover строк списка | `--hover` |
| Тонкие разделители | `--line` (0,5–1 px) |
| Текст: основной / вторичный / третичный | `--text` / `--text-2` / `--text-3` |
| Фирменный акцент (активное, фокус, «сейчас», консультации) | `--accent` |
| Срочное (сегодня, изменения) | `--urgent` |
| Цвета курсов | `--c-micro`, `--c-econ`, `--c-world`, `--c-eng`, `--c-law`, `--c-hist`, `--c-py` |
| Статусы | `--st-orange/blue/violet/yellow/green/red/gray` |
| Анимация | `--ease` (выезды, прозрачность), `--spring` (индикаторы, модалки, нажатия) |

Новый цвет не вводить. Нужен цвет — бери курс, статус или акцент.

## 3. Типографика (Onest, одна гарнитура)

- Заголовок страницы: 34 px / 500 / −0.03em (`Добрый день, Алиса`, `Учёба`, `Время`).
- Заголовок секции: 18 px / 600 / −0.02em.
- Основной текст: 15 px; вторичный: 14 px `--text-2/3`; мелкий: 12–13 px.
- Крупные числа (баллы, время): 17–34 px / 500–600, `tabular-nums`.
- Засечки не используем. Исключение — «большие моменты» онбординга (Source Serif 4, класс `ob-serif`).

## 4. Раскладка

- Контейнер страницы: `max-width: 1180px`, поля 40 px, сверху 44 px.
- Шапка страницы: слева заголовок, справа сегмент-контрол вкладок.
- Между секциями 48–56 px воздуха. **Секции без рамок**: заголовок + список на фоне.
- Карточки (`--s1`, радиус 24–26 px) — только для главного: «Сейчас», карточки курсов, форма записи.
- Сетки: 12-колоночная мысль, обычно 2 колонки (1.25fr / 1fr) или 3 карточки в ряд.
- Mobile-first: всё работает от 360 px, без горизонтальной прокрутки.

## 5а. Метаданные в строках — без склеек через «·»

Строка «Семинар · Олигополия · ауд. 3108 · Петрова Е. А.» уравнивает разные по важности сведения и читается как служебная подпись. Вместо этого у каждого сведения своё место (Material: overline / headline / supporting / leading / trailing; Linear: люди — аватаром, статус — точкой; Refactoring UI: «labels are a last resort»):

| Что | Куда |
|---|---|
| Категория, вид | Маленькая надпись над заголовком или вторая строка фразой: «Семинар «Олигополия»», «Консультация» |
| Главное | Заголовок |
| Одна вспомогательная мысль | Вторая строка: курс (с точкой цвета курса), «Практика в ауд. 4105» (`lib/phrases.ts`) |
| Срок, число, оценка, статус | Колонка справа: сверху главное, под ним мелко пояснение («Сб, 18:00» / «20% оценки»; «8 / 10» / «10 ноября») |
| Человек | Аватар с инициалами (`components/ui/teacher-avatar.tsx`), имя — в окне |
| Место, часы | Отдельный элемент со значком (`MapPin`, `Clock3`), разделение — воздухом (gap), не точкой |
| Подпись к значению | Встроить во фразу: «Записались 7 из 15», «Ответ за 3 дня», «До сессии 4 недели», «с 11:10 до 12:30» |
| Остальное | В окно (детали по клику) |

Если без перечисления никак — обычная фраза с запятой: «Международный бизнес, 2 курс».

## 6. Поведение

- Hover у всех интерактивных элементов (`--hover` или `--s2`), `:focus-visible` — кольцо `--accent`.
- Движение только при смене состояния: индикаторы вкладок, модалки, нажатия (scale .97). 150–500 мс. Никаких анимаций «появления блоков» при загрузке.
- Детали — по клику в **модалке по центру**, не на экране и не в боковой шторке. Центр уведомлений — тоже окно по центру.
- **Телефон (< 640 px):** навигация — док внизу (`Dock bottom`), окна сами становятся шторками снизу со свайпом (ничего делать не нужно — `.dlg`; длинным спискам — `sheet="full"` у `Dialog`), меню-`popover` — тоже шторкой. Нижние отступы и фиксированные элементы — с `env(safe-area-inset-bottom)` и с учётом дока (~90 px). Касание ≥ 44 px.
- Пустые состояния — одна спокойная строка («Пар нет», «Свободный день»).
- Тост внизу по центру для подтверждений («Вы записаны», «Ссылка скопирована»).

## 7. Не делай

- **Поясняющих фраз** под заголовками и у кнопок («Нажмите, чтобы…», «Используйте логин…»). Интерфейс понятен без текста.
- Разделителей через `box-shadow` на скруглённых строках: линия загибается по углам и выглядит как «стопка карточек». Только `.rows`.
- Склеек через «·» в интерфейсе (см. 5а).
- Подписей-«кикеров» над заголовками, градиентного текста, свечений, цветных полос слева у карточек, колец прогресса.
- Цветных иконок у заголовков секций, рамок вокруг каждой секции, одинаковых карточек ради карточек.
- Поиска как способа навигации (вход в поиск/ИИ — сфера в доке, Ctrl+K).
- Номера недели, реальных имён, логотипов вузов. Данные только вымышленные.
- Новых шрифтов, цветов, размеров радиусов вне этого гайда.
- Самодельных оверлеев: `div role="dialog"`, ловушек фокуса, своих обработчиков Esc, `overflow: hidden` на `body`, `z-index` для «поверх всего». Окна — `ui/dialog.tsx` (`<dialog>` + `showModal()`), меню и подсказки — `popover`, тосты — `popover="manual"`. Состояние по прокрутке — CSS (`scroll-state`, scroll-driven), не слушатель `scroll`. Сверяйся с `github.com/GoogleChrome/modern-web-guidance`.
- Полей ввода без `autoComplete`, `enterKeyHint` и нужного `type`/`inputMode`. Логины и коды — с `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}` (иначе iOS пишет первую букву заглавной). Canvas-анимации — через `lib/animate-visible.ts` (вне экрана на паузе).

## 8. Как работать

1. Новый экран — сначала HTML-макет в `docs/design/mockups/<раздел>-vN.html` на тех же токенах.
2. Скриншот через Playwright (`web/node_modules/playwright`), сам посмотри и поправь, потом покажи пользователю.
3. После утверждения — перенос в `web/` на существующие компоненты, данные через серверный слой (`src/server/data`, см. `docs/security.md`).
4. Решение записать в `docs/design.md` (раздел экрана) одним абзацем.
