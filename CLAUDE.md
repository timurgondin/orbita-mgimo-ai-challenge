# Инструкции для ИИ-агентов

Проект — «Орбита», прототип единого цифрового кабинета вымышленного «Университета Будущего» для хакатона MGIMO×AI Challenge.

## Прочитай перед работой

- `docs/ui-guide.md` — **актуальная дизайн-система для агентов**: токены, паттерны с путями к компонентам, «не делай», порядок работы. Обязателен для любой работы с UI.
- `docs/vision.md` — миссия, принципы, модули, подход, журнал решений. **Главный источник истины.**
- `docs/ТЗ — Цифровой деканат будущего.md` — исходное ТЗ и критерии оценки.
- `docs/design.md` — история дизайн-решений и описание каждого экрана (контекст; образец — ui-guide и утверждённые макеты).
- `docs/security.md` — вход, Argon2id + соль + перец, сессии, разграничение доступа. Обязателен для любой работы с авторизацией и данными.
- `docs/notifications.md` — центр уведомлений: категории, уровни важности, правила «не пропустить». Обязателен для работы с уведомлениями.

## Правила

- Пользователь руководит. Не делай ничего сверх поставленной задачи. Если сомневаешься — спроси.
- Сначала вширь, потом вглубь: не закапывайся в один раздел.
- Только вымышленные данные. Никаких реальных ФИО, логотипов, логинов.
- Безопасность: доступ к данным проверяется на сервере, пароли только в виде хеша, секреты только в env (не в коде и не на клиенте).
- Mobile-first, всё работает от 360 px.
- Современная веб-платформа: перед любой работой с HTML/CSS/клиентским JS — скилл `modern-web-guidance` (`.claude/skills/`, источник — github.com/GoogleChrome/modern-web-guidance): `npx -y modern-web-guidance@latest search "<запрос>"` → `retrieve "<id>"`. Нативные `<dialog>`, `popover`, CSS вместо самодельного JS.
- **Браузеры:** всё должно одинаково работать в актуальных Chrome/Edge, Firefox и **Safari, включая iOS** (студенты сидят с iPhone и Mac). Новые возможности платформы — только с запасным путём, который даёт то же поведение; «просто деградирует» в Safari — не годится для заметного поведения (прокрутка, закрытие, позиция).
- Новые важные решения записывай в раздел «Журнал решений» в `docs/vision.md`.

## Как работать с кодом (`web/`)

- Данные: только через серверный слой `src/server/data/*` и server actions (`src/server/*/actions.ts`); пользователь — только из `requireUser()`, никогда из запроса.
- Команды: `npm run db:push`, `npm run db:seed`, `npm run lint`, `npm run build`.
- Автопроверки (Playwright, сами поднимают сервер): `node scripts/auth-check.mjs`, `data-check.mjs`, `time-check.mjs`, `office-check.mjs`, `profile-check.mjs`, `notifications-check.mjs`, `assistant-check.mjs`, `archive-check.mjs`, `study-check.mjs`, `rating-check.mjs`, `mobility-check.mjs`, `clubs-check.mjs`, `library-check.mjs`, `print-check.mjs`. Перед сдачей задачи — **все зелёные**. Новый раздел = новый `scripts/<раздел>-check.mjs` с подделанными запросами (чужие данные, неверные параметры).
- Порты: **3000 — живое демо, не трогать**. Для проверок используй 3101+ и обязательно останавливай свои серверы в конце.
- После проверок выполни `npm run db:seed`, чтобы демо-база была чистой.
- `npm run build` перезаписывает `.next` живого сервера — после сборки его перезапускает главный агент.
- Скриншоты для отчёта — в `docs/screenshots/`.
- Коммиты делает главный агент сам, без просьбы: **после каждой законченной части** (экран, фича, раздел работы) — отдельный коммит с понятным описанием, чтобы по истории было видно, как менялся интерфейс. Не копить всё в один большой коммит, но и не дробить на коммит за каждую мелочь. Перед коммитом — проверки зелёные. После коммитов — `git push` (пользователь попросил 16.11).
